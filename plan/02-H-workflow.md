# 업무 분석 — [인사팀]

## 행위자

A1은 개인 여행 일정을 직접 제작·관리하거나, 그룹 여행에서는 호스트 역할로 일정을 제작하고 일행에게 권한별 링크를 공유하는 사용자이다. A2는 A1에게 편집 권한을 승인받아 공동으로 일정을 수정하는 일행이며, A3는 로그인한 상태로 일정을 열람하는 일행이다(보기 링크로 접속했든, 편집 권한을 요청했다가 거절당했든 경로와 무관하다).

| A  | 이름             | 역할                                                                                                         | 지금 상황                                                                                         | 현재 도구(As-Is, 실생활)                               |
| -- | -------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| A1 | 사용자(개인/호스트)    | 혼자 여행 일정을 제작·관리하거나, 일행과 함께할 일정을 제작해 일행에게 수정(A2) 또는 보기(A3) 권한 링크를 생성·발급함. 편집 권한을 요청한 사람에게는 요청자 닉네임·일정명·요청 시간이 담긴 알림을 받아 승인·거절을 처리하며, 권한 관리 화면에서 이를 확인할 수 있다                                    | 혼자일 때는 직접 검색해 동선을 짜고, 그룹일 때는 일행의 희망 장소를 취합해 동선을 짠 뒤 모임시간 전날까지 공지한다                            | 네이버 지도/구글 지도, 메모장, 폰 캘린더, 카카오톡 단톡방, 공지 고정       |
| A2 | 공동 편집 사용자(일행)  | 편집 링크로 접속해 로그인·회원가입을 마치면 A1에게 편집 권한을 요청하고, 승인받으면 Editor(A2)로 등록되어 장소 추가, 일정 수정, 동선 변경을 함께 수행함                                                                 | 가고 싶은 장소나 우선순위 변경 등의 권한을 A1과 동일하게 가진다                                                         | 카카오톡                                            |
| A3 | 열람 사용자(일행)     | 로그인 상태로 일정을 열람하는 사용자. 보기 권한을 가지며 부가 기능으로 "내 일정에 추가"를 쓸 수 있다(S17). 편집 권한을 요청했다가 A1에게 거절당한 사람, 그리고 편집 권한을 요청했지만 A1의 승인·거절 응답을 아직 기다리는 사람도 여기 포함된다(별도 대기 화면 없이 Viewer로 이용)                                                                           | 단톡방에 공지된 지도 캡처와 일정을 보고 확인한다                                                                   | 카카오톡, 네이버 지도(링크 열람)                             |
| A4 | 커뮤니티 사용자       | 다른 사람이 공개한 여행 후기·동선을 둘러보고 반응하거나 참고함                                                                        | 인스타그램·블로그·카페 등에서 다른 사람의 여행 후기를 둘러보고 좋아요·댓글을 남긴다                                               | 인스타그램, 네이버 블로그/카페, 유튜브                          |
| A5 | 비회원(게스트)       | 로그인하지 않은 상태로 열람하는 사용자(게스트). 편집 권한은 절대 가질 수 없고 열람만 가능하며, "내 일정에 추가"를 누르면 로그인 화면으로 이동하고 로그인·회원가입을 완료하면 A3가 된다                                                                                          | 포털 검색이나 지인 추천으로 여행 정보를 찾아보되, 저장·공유 없이 정보를 확인한다                                                | 포털 검색, 블로그/카페 열람                                |
| A7 | 에디터            | 커뮤니티 게시물·댓글을 관리하고, 그 흐름과 트렌드를 반영해 여행지 탐색 코너에 테마별 게시물을 작성·게시함. 후기 열람만 하는 일반 커뮤니티 사용자(A4)와 달리 콘텐츠를 직접 생산·관리함 | 커뮤니티 게시판을 수시로 확인해 신고되거나 부적절한 게시물·댓글을 처리하고, 최근 인기 검색어나 SNS 트렌드를 참고해 테마를 정한 뒤 글과 사진을 편집해 게시한다   | 게시판 관리 도구, 포털/SNS 트렌드·인기 검색어 확인 도구, 이미지·글 편집 도구 |

> 참고: 이전에 있던 "A6(서비스 관리자)"는 삭제했다. 이 문서는 사용자가 실제로 겪는 여행 일정 제작·공유·커뮤니티 흐름(As-Is → To-Be)을 다루는데, A6의 DB·서버 관리·데이터 오류 수정 업무는 사용자가 직접 겪는 화면·행동이 없는 순수 백엔드/운영 업무라 이 표의 구조와 맞지 않는다. 필요하면 별도의 "서비스 운영 업무 분석" 문서에서 다룬다.
>
> 참고: 커뮤니티(A4가 이용하는 후기 열람 등)는 비회원(A5)에게는 열람 권한이 없고 회원만 이용할 수 있다. 반면 Explore Destinations(여행지 탐색, S20)는 비회원(A5)과 회원 모두 열람 가능하다.

## 단계 (As-Is → To-Be)

> 비고: 아래 "감정" 컬럼은 별도의 사용자 인터뷰·설문 조사 결과가 아니라, 팀이 직접 겪은 경험에 근거한 추정이다.

| S   | 단계             | 행동(As-Is)                                                                     | 감정                                               | 불편                                                       | To-Be 한 줄                                                                         |
| --- | -------------- | ----------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------- | --------------------------------------------------------------------------------- |
| S1  | 개인 일정 입력       | 자신의 출발·도착 시간 등 개인 일정을 입력한다                                                    | 각자 사정이 달라 맞추기 번거로움                               | 개인별 시간 제약을 따로 취합해야 함                                     | 개인 일정을 입력하면 전체 동선에 자동 반영된다.                                                       |
| S2  | 카테고리 선정        | 동선을 짜기 전 최단거리·최단시간 등 원하는 기준을 정한다                                              | 기준을 정하는 게 번거로움                                   | 기준마다 결과가 달라 각자 비교해봐야 함                                   | 원하는 기준을 고르면 그에 맞는 동선이 바로 만들어진다.                                                   |
| S3  | 장소 정보 확인       | 방문할 장소의 휴무일·브레이크타임 등을 따로 확인한다                                                 | 헛걸음할까 걱정됨                                        | 휴무일 등을 고려하지 않고 동선을 짜면 현장에서 낭패를 볼 수 있음                    | 휴무일·영업시간을 반영한 동선을 자동으로 받는다.                                                       |
| S4  | 대중교통 확인        | 이동 구간의 대중교통 시간·배차간격을 따로 찾아본다                                                  | 대기시간이 불안함                                        | 지도 앱과 별도로 대중교통 정보를 확인해야 함                                | 동선 안에서 대중교통 시간과 배차간격을 함께 안내받는다.                                                   |
| S5  | AI 장소·동선 생성    | 블로그·SNS·지도 앱을 오가며 갈 만한 장소를 하나하나 검색해 후보를 추리고, 지도에 위치를 옮겨가며 방문 순서와 동선을 직접 짠다    | 장소를 하나하나 직접 고르고 동선까지 짜야 해 막막하고 지침                | 장소 선정부터 동선 구성까지 전부 직접 해야 해 계획 세우는 데 시간이 오래 걸림            | AI로 일정을 생성하는 기능을 선택하면 날짜와 일정 조건(날짜·여행 스타일·관심 장소·동행·이동 방식 모두 포함)을 바탕으로 방문 장소와 동선을 AI가 자동으로 생성한다. 생성 실패·결과 없음·오류 상황 모두 공통으로 에러 메시지를 안내하고 재시도 기능을 제공한다. AI가 결과를 보여준 뒤 다시 생성하는 기능을 사용하면 같은 조건으로 재생성한다. |
| S6  | 희망 장소 취합       | A1이 자신이 가고 싶은 곳을 정하고, 다른 일행에게도 가고 싶은 장소를 물어 취합한다                              | 여러 사람의 의견을 일일이 확인해야 해서 번거로움                      | 카카오톡 단톡방에 흩어진 의견을 찾아 옮겨 적어야 함                            | A1이 메신저 등으로 미리 전달받은 일행의 희망 장소를 직접 추가한다. 편집 권한이 있는 A2는 앱에서 직접 희망 장소를 추가할 수 있지만, 보기 권한만 있는 A3는 앱 안에서 제안할 방법이 없어 개인적으로 연락해 전달하는 수밖에 없다(A3를 위한 "희망 장소 제안" 기능은 없음).                                          |
| S7  | 동선 설정 및 공지     | 효율적인 동선을 설정하고 모임시간 전날까지 공지한다                                                  | 약속 전날까지 최선의 동선을 짜야 한다는 부담                        | 네이버 지도·폰 캘린더를 오가며 확인하고 공지를 별도로 고정해야 함                    | A1이 동선을 확정(=일정 생성 완료. 고정·픽스되어 수정 불가능해진다는 뜻이 아니며, 확정 이후에도 A1은 언제든 동선을 재수정할 수 있다)하면 편집 권한 또는 보기 권한 링크로 바로 공유할 수 있다. 이 공유 링크는 일정 진행 중에는 계속 유효하며 별도의 재발급·회수 절차는 없고, S21에서 일정이 종료(읽기 전용 전환)되는 시점에 함께 만료된다.                                      |
| S8  | 대화형 AI로 일정 제안  | 만들어진 일정의 항목을 하나씩 직접 수정한다                                                      | 어떻게 수정해야할지 막막함                                   | 대화하듯 자연스럽게 수정 방향을 제안 받고 싶고 다른 앱을 사용해야해서 여러 앱을 번갈아 사용해야 함                                | 대화형으로 요청하면 AI가 일정 내용을 확인하고 수정및 질문에 대해 제안을  제공한다.                                                  |
| S9  | 보기 권한 열람       | 완성된 동선을 캡처하거나 링크로 전달받아 확인한다                                                   | 확인만 가능해 답답함                                      | 오탈자나 변경 사항이 있어도 직접 고칠 수 없고 다시 요청해야 함                     | 보기 링크로 들어온 사용자는 로그인 여부와 무관하게 실시간으로 갱신되는 동선을 확인할 수 있다. 로그인 상태라면 A3, 로그인하지 않았다면 A5다.                                         |
| S10 | 편집 권한 참여       | 장소 추가나 우선순위 변경 등의 의견을 카카오톡으로 A1에게 전달하고, A1이 전체 일정에 다시 반영한다                    | 내 의견이 반영되는지 확인하기 어려워 조심스러움                       | 의견을 전달할 때마다 A1을 거쳐야 해 수정 과정이 번거로움                        | A2는 편집 권한으로 접속해 장소 추가·우선순위 변경·동선 수정을 직접 반영할 수 있다(S18에서 권한을 요청하고 S19에서 A1이 승인해야 A2가 될 수 있다). 여러 A2가 동시에 수정해도 변경이 즉시 반영되므로 별도의 충돌 처리 규칙은 두지 않는다.                                 |
| S11 | 변수 반영          | 일정 변경·짐 추가·날씨 등 변수가 생기면 동선을 다시 짠다                                             | 계획이 틀어져 불안함                                      | 변수가 생길 때마다 처음부터 다시 고려해야 함                                | 사용자가 화면에서 변수 추가 기능을 사용해 짐 추가·기상 변화·일정 지연·교통 상황 악화 등 세부 변수 항목 중 하나를 고르고 불편 정도를 선택하면, 그 결과로 시스템이 동선을 자동으로 재계산한다.                                                           |
| S12 | 실시간 일정 재조정     | 이동 중 운영시간 변동·혼잡도 변화를 알게 되면 현재 동선을 다시 확인하고 조정한다                                | 예상과 달라 당황스러움                                     | 실시간으로 동선을 바꿀 방법이 없어 그대로 진행하거나 수동으로 다시 짜야 함               | 사용자의 별도 입력 없이, 운영시간 변동·혼잡도 변화 등 실시간 변동을 시스템이 감지해 동선을 자동으로 재조정한다(여러 사람이 동시에 보고 있어도 새로고침 없이 변경 사항이 바로 화면에 반영된다). 자동 재조정된 동선은 되돌리거나 거부할 수 없다. (비고: 이 재조정은 특정 행위자가 트리거·확인하는 동작이 아니라, 서버(시스템)가 상시 감지해 처리하는 순수 시스템 동작이다 — 문장 주어가 "시스템"인 것은 의도된 것임)                                                       |
| S13 | 후기 기록          | A1/A2가 다녀온 장소의 사진과 평가를 남긴다                                                    | 기록을 남기고 싶지만 따로 앱을 써야 해 번거로움                      | 방문 기록이 흩어져 있어 나중에 찾아보기 어려움                               | A1/A2가 동선 안에서 바로 후기를 남기고 모아 볼 수 있다.                                                      |
| S14 | 후기 열람          | A4가 직접 참여하지 않은 사람의 여행 후기와 동선을 둘러본다                                            | 다른 사람의 경험이 궁금함                                   | 후기가 여러 플랫폼에 흩어져 있어 원하는 여행 동선 중심의 후기를 찾기 어려움              | A4가 공개로 설정된 후기를 목록(피드) 형태로 죽 훑어보며 열람할 수 있다.                                                       |
| S15 | 테마 게시물 작성·게시   | 최근 인기 검색어나 SNS 트렌드를 참고해 테마 주제를 정한 뒤 직접 글과 사진을 편집해 올린다                         | 트렌드에 맞는 소재를 매번 새로 찾고 글·사진까지 직접 편집해야 해 부담스러움      | 트렌드 파악부터 주제 선정, 글·사진 편집, 게시까지 전 과정을 수작업으로 해야 해 시간이 오래 걸림 | A7이 커뮤니티 흐름과 트렌드를 반영해 여행지 탐색 코너에 테마별 게시물을 작성·게시하면 사용자가 테마별 여행 콘텐츠를 찾아볼 수 있다.      |

## 흐름 (건너뛰는 단계 없는 실제 사용 경로)

* **① 혼자 사용하는 경우(A1)**: S1 → S2 → S3 → S4
* **② 보기 권한으로 공유하는 경우(A1 → A3)**: S1 → S2 → S3 → S4 → S6 → S7 → S9
* **③ 편집 권한으로 공유하는 경우(A1 → A2)**: S1 → S2 → S3 → S4 → S6 → S7 → S18 → S19 → S10 → S11 → S12
* **④ 커뮤니티를 사용하는 경우(A1/A2 → A4)**: S1 → S2 → S3 → S4 → (여행 진행) → S13 → S14
* **⑤ 에디터의 커뮤니티 운영·콘텐츠 제작(A7)**: S16과 S15가 병행된다. S16은 커뮤니티 게시물·댓글을 상시 관리하는 운영 업무이며, S15는 커뮤니티 흐름과 트렌드를 반영해 여행지 탐색 코너의 테마 게시물을 제작·게시하는 업무이다.
* **⑥ AI로 장소·동선을 생성하는 경우(A1)**: AI로 일정을 생성하는 기능을 선택 → S5. S5에서 장소와 동선이 자동으로 생성되며, 이후 필요한 경우 생성된 일정을 확인·수정하고 공유할 수 있다. AI로 생성한 일정은 A1 역할로 동선 제작 화면에 넘어가 흐름 ① ~ ③ 에서 다루는 일반 일정 제작·공유 흐름(S1~ S4, S6~ S7, S10 ~ S12, 편집 권한 공유 시 S18~S19 포함)과 합류한다.
* **⑦ 로그인한 보기 권한 사용자가 일정을 저장하는 경우(A3)**: S9 → S17. 로그인하지 않은 A3는 S9에서 열람만 하고 흐름이 끝나며, 로그인한 경우에만 S17로 이어져 내 계정에 저장할 수 있다.
* **⑧ 비회원의 서비스 둘러보기(A5)**: S20. 로그인 없이 여행 정보를 탐색하는 비회원의 독립적인 진입 경로로, 위 ①~⑦ 흐름과는 별개로 발생한다.
* **⑨ 일정 종료 후 처리(①~⑦ 공통 종착점)**: (①~⑦ 중 어느 경로로 진행되었든) → S21. 일정의 마지막 날짜가 지나면 흐름의 마지막 단계로 S21이 이어져, 해당 일정은 읽기 전용 상태로 전환된다.

### 분기

S7(동선 설정 및 공지) 이후 A1이 발급한 권한에 따라 경로가 나뉜다. 로그인 상태로 열람하는 A3는 S9에서 일정을 열람하고(보기 링크·편집 요청 거절 등 경로 무관), 편집 링크로 들어와 S18에서 권한을 요청하고 S19에서 A1의 승인을 받은 A2는 S10에서 직접 일정 수정에 참여한 뒤 여행 중 변수 반영(S11)과 실시간 재조정(S12)까지 이어진다.

S8(대화형 AI로 일정 수정)은 특정 시점에만 발생하는 단계가 아니라 일정 제작·수정 과정에서 수시로 활용할 수 있는 보조 기능이므로 기본 흐름에서는 제외한다.

S13(후기 기록)은 여행을 마친 A1/A2가 수행할 수 있으며, 후기를 공개로 설정한 경우 A4가 S14에서 해당 후기를 열람할 수 있다.

일정을 만들 때 장소를 직접 추가하는 방식과 AI로 생성하는 방식, 두 경로로 나뉜다. 장소를 직접 추가하는 방식을 선택하면 기존의 일정 제작 흐름으로 이어지고, AI로 생성하는 방식을 선택하면 S5에서 방문 장소와 동선이 함께 자동 생성된다.

S15와 S16은 A7이 수행하는 커뮤니티 운영 업무로, 여행 일정 제작 흐름(S1~S14)과는 별개의 업무이다. S16은 게시물·댓글 관리, S15는 테마 콘텐츠 제작·게시를 담당하며 두 업무는 필요에 따라 병행된다.

S9(보기 권한 열람)는 로그인 여부와 무관하게 가능하지만, S17(내 일정에 저장)은 로그인한 사용자만 이어갈 수 있다. 비회원(A5)은 편집 권한을 가질 수 없고 열람만 가능하며, 편집 권한(S10)을 가지려면 반드시 로그인이 되어 있어야 한다.

A1이 원본 일정을 삭제하면, 그 시점에 실시간으로 접속해 있던 A2/A3 화면에는 "삭제된 일정입니다" 안내가 뜨며 더 이상 접근할 수 없다.

A1이 탈퇴하거나 계정을 삭제해도 그룹 일정은 삭제되지 않고 그대로 보존되며, 읽기 전용(편집 불가)으로 전환된다. 다른 A2에게 소유권이 넘어가지는 않는다.
